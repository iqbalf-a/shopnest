I

Peta service

Gateway adalah satu-satunya pintu dari luar. Ia memverifikasi JWT, lalu meneruskan identitas sebagai header X-User-Id / X-User-Email / X-User-Role — service percaya pada gateway, bukan pada client. Panggilan antar service (order → product saat checkout) lewat OpenFeign dan tidak menyentuh gateway sama sekali — justru karena itu /api/products/{id}/stock/reduce ditolak gateway (403) untuk panggilan dari luar: Feign tetap bisa, browser tidak. Gateway juga menjawab preflight CORS sebelum pemeriksaan token, dan tiap service memeriksa sendiri apakah id di path cocok dengan X-User-Id — gateway membuktikan siapa, service memutuskan boleh apa.

← geser untuk melihat penuh →

Hanya /api/auth/** dan /docs/specs/** yang lolos tanpa token; sisanya ditolak gateway sebelum menyentuh service mana pun. Kotak bergaris putus-putus adalah infrastruktur — bukan jalur request.

II

ERD — enam tabel, empat schema

Setiap tabel digambar di dalam jalur service pemiliknya, karena di situlah letak batasannya: foreign key hanya boleh ada di dalam satu jalur. Kolom seperti orders.user_id memang menunjuk ke auth_service.users, tapi tidak ada constraint yang menjaganya — relasi itu dipegang oleh API dan disiplin kode, bukan database.

← geser untuk melihat penuh →

Foreign key sungguhan (satu schema) Referensi lintas service — tanpa FK PK Primary key FK Foreign key REF ID milik service lain

Semua tabel mewarisi created_at / updated_at dari BaseEntity, diisi otomatis oleh JPA auditing. Tabel dibuat Hibernate lewat ddl-auto=update saat service startup — docs/schema.sql adalah snapshot hasilnya, bukan migrasi.

III

Perjalanan satu checkout

Satu alur yang menyentuh hampir semua bagian sistem, dari token sampai snapshot harga.

LANGKAH 1

POST /api/orders

Client mengirim daftar productId + quantity beserta Bearer token ke gateway.

LANGKAH 2

Gateway membuka token

JWT diverifikasi, lalu X-User-Id ditempelkan ke request yang diteruskan ke order-service.

LANGKAH 3

Feign → product-service

Tiap item diambil detailnya, lalu stok dikurangi lewat /stock/reduce. Stok kurang → order gagal.

LANGKAH 4

Snapshot, bukan referensi

Nama dan harga produk disalin ke order_items. Harga katalog boleh berubah besok; struk tidak ikut berubah.

LANGKAH 5

Order tersimpan PENDING

total_amount dijumlahkan dari subtotal item, status awal PENDING, menunggu PAID atau CANCELLED.
